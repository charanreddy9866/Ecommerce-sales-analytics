# E-Commerce Sales Analytics

A business intelligence project that analyzes sales performance, customer behavior and product revenue for an online retailer, using **SQL, Python and Power BI**.

It covers the full analytics workflow: raw data → data-quality checks → a clean sales model → analytical SQL → dashboard-ready outputs.

> The dataset is synthetic (generated by `scripts/generate_data.py`) so the project can be shared publicly. It models two years of orders with seasonality, repeat customers and deliberately injected data-quality problems.

## Business questions

1. How is revenue trending month over month, and what are the seasonal peaks?
2. Which products and categories drive the most revenue?
3. Which products lead each month?
4. How do customer segments differ in order frequency, spend and repeat purchasing?
5. Which channels and regions contribute the most revenue, and where are returns highest?

## Architecture

```
data/*.csv  ──►  sql/01_schema.sql          raw tables (customers, products, orders, order_items)
                 sql/02_data_quality.sql    duplicate, missing-value, invalid-value and orphan checks
                 sql/03_clean_model.sql     fact_sales view: deduplicated, cleaned, enriched
                 sql/04_analysis.sql        joins, CTEs, aggregations, window functions
                        │
                        ▼
                 reports/*.csv  ──►  Power BI dashboard (revenue, orders, trends, top products)
```

`scripts/run_pipeline.py` runs everything end to end in DuckDB. The SQL is written in PostgreSQL-style syntax so the same files can run on Amazon Redshift (see `aws/`).

## Dataset

| Table | Rows | Description |
|---|---|---|
| customers | 12,000 | signup date, region, segment |
| products | 120 | 6 categories, list price |
| orders | 25,000 | order date (2024–2025), channel, status |
| order_items | 43,144 | product, quantity, unit price (raw, includes bad rows) |

## Data-quality checks

| Check | Failing rows | Handling in `fact_sales` |
|---|---|---|
| Duplicate line items | 60 | Removed with `ROW_NUMBER()` dedup |
| Missing product names | 40 | Repaired from the products table |
| Zero or negative prices | 30 | Excluded |
| Zero quantities | 15 | Excluded |
| Orphan line items | 0 | — |

Results are written to `reports/data_quality_report.csv` on every run.

## SQL techniques

- **Joins** across four tables to build the `fact_sales` model
- **CTEs** for multi-step logic (monthly totals, per-customer rollups, ranking)
- **Aggregations** for revenue, orders, average order value, units and repeat rate
- **Window functions**: `LAG()` for month-over-month growth, `RANK()` for top products per month, `ROW_NUMBER()` for deduplication, running `SUM() OVER` for cumulative category share

## Key findings

- **$9.5M delivered revenue** across 22.5K orders; 2025 revenue grew **7.8%** over 2024.
- **Seasonality:** December and November are the peak months, at roughly 1.7× and 1.4× an average month.
- **Category concentration:** Electronics produces **58%** of revenue; the top three categories make up 86%.
- **Channels:** Web drives about 50% of revenue, Mobile App 35% and Marketplace 15%.
- **Returns:** return rates are similar across categories (5.7–6.6%), highest in Apparel.

## Dashboard

The Power BI report (`dashboard/ecommerce_sales.pbix`) uses the CSVs in `reports/` as its data sources. Planned pages:

1. **Overview:** total revenue, orders, average order value, MoM growth cards and a monthly revenue trend
2. **Products:** top 10 products, top 3 products by month, category share
3. **Customers:** segment comparison, repeat rate, revenue per customer
4. **Channels & regions:** revenue by channel and region, return rate by category

## Run it

```bash
pip install duckdb pandas matplotlib
python scripts/generate_data.py   # writes data/*.csv
python scripts/run_pipeline.py    # DQ checks, clean model, analysis -> reports/
```
